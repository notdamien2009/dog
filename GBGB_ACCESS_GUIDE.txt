QUICK START
1. Copy this v1.3 update into your existing DOG RACE folder.
   If asked to overwrite existing .py/.bat/.txt program files, select yes.
   Do not delete your data/ folder or dog_race.sqlite3 database.
2. Double-click RUN_GBGB_PILOT.bat for 2024-06-01 and 2026-11-16.
   Confirm there are results and meeting records; share any unexpected output.
3. Double-click RUN_GBGB_3_YEARS.bat to collect 2023-11-18 to 2026-11-17.
4. Run GBGB_CHECK_STATUS.bat to review counts. Interrupted runs resume.
5. Later, RUN_GBGB_OLDER_YEARS.bat covers 2020-11-18 to 2023-11-17,
   provided your access permission covers the earlier dates.

WHAT IT DOES
- Reads the JSON index for each date, pages through all returned results.
- Fetches each distinct meeting found and keeps original JSON in data/raw/gbgb.
- Stores index and meeting JSON in dedicated data/gbgb.sqlite3 for future mapping.
  Australian data stays in data/dog_race.sqlite3. GBGB raw JSON is still under data/raw/gbgb/.
- Prints per-day progress and each meeting ID in the Windows CMD window.
- Waits at least 3 seconds after every new request.
- Stops on actual server 401, 403, or 429 (no bypasses, rotation or CAPTCHA).
- Makes no uploads to GitHub, Supabase, cloud or any third party.

IMPORTANT QUALITY LIMITATION
The field mapping from real full-meeting JSON still needs live verification.
This version records complete JSON intact but does NOT yet generate validated
speed figures or a fully normalised UK runner-results table. Do not interpret
a successful download as complete/clean three-year coverage.

API documentation has examples, but the ZIP was tested OFFLINE only.
Live access from the packaging environment was unavailable due to DNS.
The pilot on your PC is essential to prove the endpoint works.

DATABASE LOCK FIX IN v1.3
- GBGB no longer opens the Australian/shared SQLite database.
- Previously downloaded GBGB raw JSON is reused on a resumed run and imported
  into the separate UK database. Nothing is deleted or overwritten in the
  previous data/dog_race.sqlite3 database.
- SQLite WAL plus a longer busy timeout improve recovery from ordinary contention.
- Two new GBGB collectors started in the same folder cannot run concurrently;
  the second displays a clear error instead of racing for the same database.
- Do not delete .sqlite3, .sqlite3-wal, or .sqlite3-shm files to clear a lock.
- If your DOG RACE folder is inside OneDrive / Dropbox / a synced Desktop,
  consider moving the WHOLE folder to a local non-synchronised path such as
  C:\DOG RACE before starting long archive collection. Cloud syncing active
  SQLite databases can cause locking problems. Close all BAT windows first.
