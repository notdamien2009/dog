DOG RACE GBGB v1.4 - WINDOWS TEST CLEANUP FIX (18 November 2026)

REPORTED SYMPTOM
RUN_TESTS.bat ends with WinError 32: temp\...\gbgb.sqlite3 is being used
by another process; FAILED (errors=1) despite 25 tests executing.

ROOT CAUSE
One test used `with gbgb.open_db() as new:` and assumed the SQLite
connection was closed. Python's sqlite3 context manager only commits or
rolls back; it does NOT close. On Windows the tempfile cleanup therefore
failed because the open database handle prevented deletion.

CHANGES
1. The GBGB test now explicitly closes that connection via
   contextlib.closing(); checks it is truly closed before temporary-file
   cleanup. No sleep, garbage collection or deletion of SQLite journal files.
2. The Australian collector's main database connection now closes
   explicitly too, preventing the same problem on command exit.
3. The CSV audit tool closes the database even if a report fails.
4. Preserves separate data/gbgb.sqlite3 and data/dog_race.sqlite3 databases.
   Raw files, saved data and checkpointing are unchanged.

INSTALL
Close DOG RACE commands. Copy this patch's DOG RACE folder contents
into your current DOG RACE folder and replace matching files. Do not
delete/overwrite data/. Then run RUN_TESTS.bat. If it passes,
run RUN_GBGB_PILOT.bat.

VERIFICATION
26 offline tests passed on Linux, including a new explicit-close regression test. Windows/GBGB live API
needs confirmation on the user's machine.
